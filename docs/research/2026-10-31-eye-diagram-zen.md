# 开眼：用眼图看 Orchestra（2026-10-31）

## 1 眼图教给我们什么

眼图是把成千上万个比特周期的波形叠在同一张图上。中间那块空白叫「眼」，眼睁得越大，接收端越不会读错。眼开不开只看三件事。第一，判决点（接收端判 0 还是 1 的那一刻）看到的符号少而分明。第二，每个符号都在一个有界、量过的时间窗里到达。第三，多次叠加落在同一条线上。

r4 读别人数据的那一侧已经很像一只张开的眼：看 size 不看 mtime，看 pid 加创建时间，按 seq 去重，已读要有回合开始的证据。闭眼的地方多在 Orchestra 自己身上。Event 的时间没说是谁的钟，睡眠和对时跳变一字未写。timedOut 一个词有三个意思。有的非终态既没有钟也没有主，迟到的回信就掉进这种缝里。

DS-Bot 的三个故障正好是三种闭眼（docs/research/2026-10-30-ds-bot-noticed.md）：
- 截断的回合和完成的回合长成一个样子；
- 已读标记跑在投递前面；
- 迟到的结果没有状态可去。

所以开眼主要靠减法和测量，不靠再加护栏。已定规则一条不松。这些改动只会让东西更早关闭、更早被看见，从不替你决定，也从不打断回合。

## 2 开眼准则

**P1 一符一义**（垂直张开：眼的上下开口，指 0 和 1 离得够远）
- 准则：结局或搁置只要需要你采取不同的动作，就是不同的符号，状态和卡一一对应。「回合结束」和「完成」只来自正证据。看不清就判「不明」，不硬判，也不重发。
- 测法：每个结束类在每个界面面上做零 token 渲染用例，渲染结果相同的类对数为 0（有文档的导出例外除外）。回合中途杀进程、cancel、maxTurns、断连，被显示成「回合结束」0 次。cause 为空的终态 0 条。
- 触及：§6.3、§8.3 规则 1、§8.6、§6.1 InboxItem、§11.2、D19、A16。

**P2 每个非终态都有钟、有主或有闸**（游程上限：8b10b 这类编码保证不会长时间没有跳变，否则接收端失锁）
- 准则：任何等待恰好有一个放行人：一条具体打开着的条目 id（不能写成「你」）、一个活句柄、一只钟，或一个 governor 名额。到点只写一条边，即换标签或出它本来就有的那条条目，从不去动 agent。queued 到点受原则 4 约束，只换标签、不拒绝。闲置的 Part、你名下打开着的条目算静止态，单列。
- 测法：驻留表覆盖全部非终态。每次 journal 提交后，「无钟、无主、无闸」的行恒为 0。假时钟把每个非终态推到上限的 2 倍，每个都写出了边，自动重投、续跑、中断都是 0 次。
- 触及：§6.3、§6.4、§6.1 Part 与 Wish、§8.9 (g)、原则 4、原则 15、D16。

**P3 时间分两份报**（抖动分解：把跳变时刻的偏差拆成有上界的确定性部分和只能统计的随机部分）
- 准则：每个时延或超时数字写成「确定性上界 + 随机尾部@目标率（假设）」。前者在假时钟下证明，后者按来源实测。每个计时器行注明数字来源，改值要有 Decision。
- 测法：M0 每个时延门槛两行都有数。相位扫描下，确定性部分超上界 0 次。尾部按三段报：harness 侧压住、我方采样、我方提交。CI 断言每次计时器改值都对得上一条 Decision。
- 触及：§13.2 L2367、L2384、L2386；§14 第 3、12 行；§10.12。

**P4 时间是输入，次序只认流**（确定性重放：叠加的迹线逐条重合）
- 准则：次序只来自各源自己的 seq 和 journal 序号。时长用单调钟，日历才用墙钟，别人的时间戳只当数据。引起转换的定时器触发要写成一条 journal 事件，每次转换写明 cause：源、你、还是钟。安全方向的计时取最先到点的那只钟。
- 测法：
  - 同一 fixture 以 0.1×、1×、10× 回放，以 100 ms 和 1 s 轮询，转换逐字节相同。
  - 打乱 srcTime，注入睡眠 8 h，墙钟跳 ±1 h，提前或推迟触发都是 0 次。
  - 删掉一条引起转换的 clock 事件，回放必然分歧。
- 触及：§6.1 Event、§13.2 L2383、L2386、D10、§8.1 deadline、§10.9。

**P5 标记后于效果**（建立时间：数据要先于时钟沿稳定，否则锁进去的是错值）
- 准则：已读、游标、已触发、已见这些标记，只能晚于它所证明的效果，或与效果在同一个确定的提交点一起提交。toast 和浏览器通知进不了事务，按至少一次投递处理，以 itemId 当 tag 去重。
- 测法：崩溃点扫描下事件丢失 0、重复 0（重复只按 InboxItem 行计，不按系统 toast 计），提醒丢失 0。
- 触及：§5.2 Store L560、§6.1 sourceCursor、§6.3 L728、§7.1 L816、§11.2 L2105。

**P6 细迹线、无串扰**（串扰：邻线的信号耦合进这条线）
- 准则：核心只消费一张小符号表，只认邮局这一条总线。封闭乐章（复核、愿望执行）只收发给它的信，由邮局在接纳时强制，不靠派发正文。
- 测法：核心目录 grep 不到 harness 名（M0 先只告警）；复核进行中，串进复核乐章的信封数为 0。
- 触及：§3.1 原则 1、7、11；§5.2；§8.9 (e)；A8。

**P7 眼图本身是测量**（模板测试：在眼中央画一块禁区，任何迹线碰到就判失败）
- 准则：
  - 每条已定规则写成只读 journal 的纯函数，在零 token CI、回放、线上三处跑同一份代码。
  - 先用故意做坏的样本证明它能命中。
  - 报四个数：触发次数 N、命中数、离禁区最近的距离、命中率上界。N = 0 显示「未测」，不写「通过」。
  - 模板结果是计算出来的文本，没有人的权威，只记台账，不改状态。
  - 余量只给你看、不自动放宽，这一条 r4 已有。
- 测法：每个模板都有坏样本校准；Z（零写入）、H（人类动词）、C（完成主权）三个模板线上命中 0；附录 F 每条用例都映射到至少一个模板。
- 触及：§14、附录 F、A5、§5.3、§13.2 L2389、D8、D19。

## 3 想法清单

### 放进 M0 计划

- **补1 journal 与 db 谁是权威**（复核补充）：r4 只列了 orchestra.db 和 journal.jsonl 两份存储，没写谁是权威、按什么顺序提交、崩溃后两者对不上怎么恢复。M0 二选一写明：journal 追加并 fsync 在先、db 是可重建的投影，或者反过来。
  开眼：I01、I02、I14(c) 和「黄金回放完全一致」都以它为前提。测：崩溃扫描后从权威一侧重建另一侧，逐行一致。成本：决定小，重建器中。
  锚：§5.2 L560、L522；§13.2 L2383。
- **I04 Event 的时间字段拆开**：ts 拆成五个字段。srcSeq；srcTime（可空，注精度）；obsMono 与 obsWall（我们读到的时刻）；jseq（journal 序号）。InboxItem 加 committedAt、notifiedAt。srcTime 永不参与排序或计时，由 CI 断言。
  开眼：Event 表在 M0 定型前改几乎零成本，定型后就要迁移；它也是 P3 三段延迟的数据来源。测：srcTime 平移、倒序、混用时区，转换都不变。成本：小。
  锚：§6.1 L648；§7.1 L816（Codex 文件名是本地时间）、L841；§13.2 L2383–2385。
- **I01 定时器触发写进 journal**：只设一个 Clock 端口、一张时钟表。只记引起转换的触发 {timerId, 哪只钟, durationMs, firedMono, firedWall}，不记 tick。每次转换带 cause：source(partRef, srcSeq)、human(actionId) 或 clock(timerId)。同一 tick 到期的按固定全序处理：先收往安全方向的，再出请你中断的 P1，再出回访与提醒，最后是摘要。
  开眼：时间成了输入，回放才可能完全一致，「截止到了」和「回合结束」也第一次在数据里分得开。clock 事件只改状态、出条目，不新增唤醒源，D16、Q-P10 不变。先例：Arrangement 已禁 Date.now，并把 budget() 写进 journal。
  测：三种速度回放，转换逐字节相同；同 tick 5 个定时器乱序插入跑 100 次，结果一致。成本：小。锚：§13.2 L2383、L2386；§5.2 L580；D10 L494；L1095。
- **I02 标记后于效果**：M0 落两处。一是源游标和解析出的 Event 行放在同一个 db 事务里。二是提醒的「已触发」晚于 journal 追加并 fsync。外部通知按补3 处理。
  开眼：几乎零成本，堵住 DS-Bot「已读先于投递」的整类变体。S1-DSH-06 的「游标在 ingest 前就加上块长」是同一类错。测：崩溃扫描下丢失 0、重复 0；24 h 观测里看同事务写入吃不吃 2 s 预算。成本：无到小。
  锚：§6.1 L638；§6.3 L728；§7.1 L816；§13.2 L2386；spikes/s1-dsh/REPORT.md。
- **补2 派生判定写进 journal**（复核补充）：A2A 正文放在可清除的表里（TTL 14 天，可「清除秘密」），只有 Arrangement 的正文钉住。依赖正文的判定要把结论本身写进 journal：只致谢长度、处置 schema 解析、origin、脱敏结果。回放只读这些判定，不重算。M0 定格式，M1 落地。
  开眼：正文被清掉之后，回放仍落在同一条线上。测：清掉一批正文再回放，转换不变。成本：小。锚：§6.1 L667、L669；L1155；§13.2 L2383。
- **补3 通知按至少一次投递**（复核补充）：r4 没写重启后那些已提交、却不知道弹没弹出的通知怎么办。改为浏览器 Notification 和 toast 的 tag 都取 itemId，崩溃后补发的会叠成一条。
  开眼：「提醒不丢」第一次有了明确含义。测：在提交后、弹出前杀掉守护进程，重启后可见通知 1 条，InboxItem 1 行。成本：小。锚：§11.2 L2105；§13.2 L2386。
- **I09 判决点只认一张小符号表**：约 10 族：part.seen/gone、turn.open{origin}、turn.close{结局}、ask.open/close、delivery.read、tool.call/result、child.open/close、usage、context.pressure、guard.native、anomaly。收件箱、状态机、检测器、邮局、账本只消费这张表。完整 AgentEvent 留给乐手页和回放。M0 只做表和 lint 告警，不卡 M0 出口。
  开眼：判决点看不出信道多烂，眼才稳。这张表也是原则 1「控制依赖的事件类型覆盖率 100%」的分母。测：每个符号在每家黄金回放中的覆盖率，控制依赖的行要 100%。成本：小。
  锚：§3.1 L428、L434、L438；§5.2 L552；§13.2 L2373；§8.9 (g) L1344；§10.3 L1568。
- **I11 别人的时间戳只比相等**：Claude 注册表的 statusUpdatedAt 只和它自己上一次的值比相等；变了就是新的一段等待。「在等你」的去重键改为 (根, pid, procStart, statusUpdatedAt)，另记 missedTransitions 计数。顺手修一处自相矛盾：§10.12 的「最近 10 min 修改的文件」改为「size 变过的文件」。
  开眼：这条防混叠（采样太稀，两次跳变被看成一次）。S5 静态分析显示 statusUpdatedAt 多半只在状态变化时才变。测：200 ms 内两次审批得到 2 条条目；上线前先用 S5 的被动轮询数据核一遍。成本：无到小。
  锚：§7.1 L816、L830；§13.2 L2367、L2385；§10.12 L1752；spikes/s5-claude/REPORT.md。
- **I12 单写者锁看身份，不看心跳**（减法，见第 4 节）：锁文件写 (pid, createTime)。只有这个身份的进程已经不存在，新实例才接管。再加一道内核互斥：独占监听一个命名管道。
  测：把 orchestrad 挂起 120 s 再启动第二个实例，接管 0 次、journal 分叉 0 次、提示 1 条；两个实例同时启动，恰好活下 1 个。libuv 对同名管道第二次 listen 会不会报错，M0 实测。成本：小。
  锚：D3 L487；原则 8 L435；§10.5 L1602；L1018；§13.2 L2370。
- **I06 + I17 M0 验收按测量写**：
  - 每个时延门槛写两行：确定性上界，加随机尾部目标率。目标率例如 P(>2 s) ≤ 1e-3（假设，由你定，不卡 M0 出口）。24 h 观测按 Wilson 95% 上界报告，并按来源拆开。
  - 「漏掉的提醒 = 0」改为按信号类别报漏报、迟报、误报三个率。
  - §10.12 每个静默阈值注明该源实测的最大静默：DSH 写盘最长压 5.1 s；Claude 注册表 spawn 后 28–46 s 才出现；合法的 input needed 等待长达 678 s。CI 断言阈值大于录下的最坏值。
  开眼：这不是放宽 ≤2 s。确定性部分收紧，尾部从「例外」变成测量。一天二十来条审批没漏，只能说明漏报率 ≤15%。注意 spike 是在 CPU 83–100% 下测的，尾部偏悲观、也不稳定，不能当基线。成本：措辞为主。
  锚：§13.2 L2367、L2384、L2386–2387；§14 L2719、L2728；§10.12 L1753；§7.1 L828–830；docs/spikes/2026-10-29-m0-spikes.md L55。
- **I08 睡眠与时钟跳变（M0 只做 clock-gap）**：procguard 加一个 clock 命令，一次返回墙钟、含睡眠的中断时间、不含睡眠的中断时间。醒来时比较差值，记一条 clock-gap（「机器睡了 7 h 12 min；期间 3 条审批已按超时拒绝」），并写明一次性提醒跨睡眠怎么处理。审批与租约取「最先到点的钟」随 M1 的审批队列做。信封 deadline 改存 {startJseq, startMono, durationMs, domain}，也在 M1。
  开眼：这是 r4 唯一完全空白的时间轴，一次睡眠会让所有定时器在同一刻翻转。测：注入睡眠 8 h，只出 1 条 clock-gap；跨 gap 的延迟样本单独标出，不进 p99；你在场时真机睡眠一次。libuv 定时器在睡眠期间走不走，本机未实测。成本：小。
  锚：§8.1 L925；§10.9 L1661；§13.2 L2386；§11.2 L2105。
- **I10 锚点缺席时只看边沿，不判电平**：版本在契约包外时，靠锚点才判得出的状态一律低置信，显示「活动中 / 不明」。边沿类信号（有活动、tool.call 计数、RSS）保持全置信，runaway 刹车不会变瞎。处于 working、超过 T 没有任何锚点，就转为 unknown，T 取自 I17 的静默表。
  开眼：均衡（接收端补偿信道损耗的滤波）没校好时，跳变看得见，电平分不清，硬判只会判错。原则 7 管解析失败，管不到「结束事件改了名」。M0 的实际情形是 Claude CLI 漂移和 DSH。测：结束事件改名的 fixture，T 内变为 unknown。成本：小。
  锚：§3.1 L434；§7.2 L848、L851；§13.2 L2372。
- **I14 压力眼 (a)(b)**：(a) 相位扫描：用假时钟让事件落在轮询 tick 的 0 到 7/8 处，同时扫「挂上时刻相对写入的偏移」，因为 S1-DSH 的 5.6 s 是挂上之前已写下两帧。(b) 源抖动：同一串写入按 100 ms、250 ms、1 s 轮询并随机切块重放，包括先截短再追加、rollback、同路径换文件。(c) 崩溃点扫描移到 M1，前提是补1。
  开眼：只在一个相位上测过的眼不算张开。测：漏检 0，各变体之间派生序列差异 0，CI 时长设上限。成本：小。扫描会产出大量 unknown，这正是「不明不重发」，不能为了好看改成自动重发。
  锚：§13.2 L2367、L2377、L2383；§14 L2717；spikes/s1-dsh/REPORT.md L72–74。
- **补5 探头负载**（复核补充）：观察器本身也在给信道加载：每 250 ms 一次 fstat、注册表 1 s 轮询、解压。24 h 观测里记下 orchestrad 自己的 CPU 和 IO，并做一次观察器开、关对照。
  开眼：示波器探头也有负载，量到的抖动里有一部分是我们自己造的。测：开、关两组的 p99 之差。成本：小。锚：§13.2 L2393（只量 RSS）；m0-spikes L55。

### 留到后面的里程碑

- **I03 迟到回信照常结算（M1）**：timedOut 从终态改为 working 上的「已超时」标记。截止照旧出条目，wait 照旧按时返回。回合之后自己结束时，记 replied(late)，投给请求方，唤醒一次（计入规则 7 的 20 次、跳数和 calls(n)）。那条 timedOut 条目原地加注「回信已到」并 auto-cleared，不出第二条推送。
  开眼：迟到回信是上一槽的拖尾（ISI，码间干扰：前一个符号的拖尾漏进下一个），它要照常结算，不能掉进缝里。还要写清：愿望 Task 超时后带 done 结束，发不发复核。测：截止 30 min、第 41 min 回信，请求方恰好醒 1 次，新增 P1 推送 0 条。成本：小。
  锚：§6.3 L716、L732；规则 1 L965、规则 8 L972；§6.5 L781；§6.4 L766。
- **I05 一套结局词表（M1 写代码前）**（减法，见第 4 节）：Exchange 终态、规则 1 的回信状态、ArrangementCall.outcome、wait 返回值，共用 end + cause 加三个标记（overdue、late、suppressed）。「不明」只留一个词；如果要分，就用两个不同的名字（「投递不明」和「结束方式不明」）。ended 只来自契约包写明的原生结束标记。
  测：每家 fixture 里，中途杀进程、cancel、maxTurns、TRANSPORT 被记成 ended 0 次，cause 为空的终态 0 条。
  锚：§6.3 L713–733；§8.6 L1058–1059；§6.1 L643、L655；L1383、L2094；A16 L3420。
- **I07 驻留表与不变式（M1；M0 先覆盖 InboxItem 和一次性提醒）**：§6 加一张表，每个非终态填上钟、主或闸。每次提交后跑一条 SQL 查缝。每个钟自动生成 T−ε 与 T+ε 两条用例。不做 Hold 表重构。已知缺上限的有：排在 governor 后面的 reply、notice、progress；已投递却没开回合的信；Part 的 starting；queued、held、waiting 期间的信封 deadline。

## 7 第二轮：权力、人这一端、开发信道、减法（2026-10-31 下午）

第二轮的材料是 M0 第 1 步。写围栏、读闸门、导入围栏做完后，两位复核者找出 12 个漏洞，形状几乎一样：某个模块不用别人交给它，按名字就拿到了一种权力。这一轮从四个角度看，每个角度配一个唱反调的代理逐条反驳。28 条想法里，否掉 1 条，原样保留 1 条，其余 26 条都改了形式才留下。下面只写改过之后的样子。证据都在 Node 24.22 上实测过，探针放在 `os.tmpdir()`，用完即删。

### 7.1 新准则

**P8 每条线只有一个驱动者**（总线争用：同一条线上两个驱动器同时出力，谁也读不准）
- 准则：权力靠递交，不靠够得着。boot 是唯一的装配处，在上锁前拿走守护进程合法需要的能力，再递给唯一该用它的模块。其余的要么锁成抛错的桩，要么在一张表里写明为什么无害。
- 测法：
  - 冻结一份键集：钉死的 Node 上，`globalThis` 和 `process` 的全部自有属性名，在两个时刻各记一份，一份在装好围栏之后，一份在 working 图全部加载之后。之所以要第二份，是因为 undici 的两个 dispatcher symbol 要等到 import `node:http` 之后才出现。键集多一个或少一个，CI 就变红，逼一次只针对差量的分类提交。
  - 只对大约 15 个能碰到 I/O、进程、网络或调试器的键手工分类，不逐个分类所有键。每把锁配一个子进程 PoC，再配一个不装围栏的对照组，对照组必须成功，以此证明测试真的在测。
  - 启动时 `process.version` 和键集记录的版本不一致，Tuning 里显示一行，不切模式，也不弹提示。
- 余量（照实说）：模块从 `process.stdout` 的原型链仍能拿到 `net.Socket` 并连出 TCP。stdout 是 console 要用的，没法当端口拿走；而锁掉 `Socket.prototype.connect` 会连 undici 自己的出站一起锁死。所以名字围栏和静态扫描管的是我们自己写的代码，而不是恶意代码。harness 的内容只是数据，到不了这一层。键集测试保证这块残留不会悄悄变大。

### 7.2 实测出的洞（第 2b 步就补）

- **跨进程开调试口。** 任何模块调用 `process._debugProcess(pid)`，都能让同一用户的另一个 Node 进程打开 9229 调试端口，DSH 就跑在 Node 上。这其实是换了个名字的 `node:inspector`。三个代理各自复现过。补法：把 `_debugProcess`、`_debugEnd` 锁成桩。
- **能关掉单写者锁。** `process._getActiveHandles()` 会交出活着的 Server 对象。任何模块都能 `.close()` 掉锁的命名管道，内核互斥就松开了，而守护进程还在照常写。补法：把 `_getActiveHandles`、`_getActiveRequests` 锁成桩。`getActiveResourcesInfo` 只返回类型名字符串，留着当诊断用。
- **undici dispatcher 后门。** 不调用 `fetch`，用 `globalThis[Symbol.for('undici.globalDispatcher.1')].request()` 一样能发出 HTTP（返回 200）。把它换成 Proxy，还能截到 boot 亲手递出去的 `ports.fetch` 的请求路径；到第 15 步，这条路径里会带 DSH 的 `/connect` token。补法：
  - 装围栏时，把 `.1` 和 `.2` 两个 symbol 预先定义成冻结、抛错的桩。实测之后 import `node:http` 和 `data:` fetch 都照常工作。
  - 第 15 步：boot 在上锁前先 `await fetch('data:,')` 一次，把 undici 实例化出来，这一步不走网络；再拿到 dispatcher，通过 `init.dispatcher` 绑进 `ports.fetch`。
- **SpawnGate 的白名单是构造参数。** 第 2 步把 toast 脚本、csc 源、`/out:` 判定、procguard 路径都做成了构造参数，任何模块都能拿自己的 PowerShell 脚本 new 一个 SpawnGate。这偏离了计划 L404 和 §2 原文。第 2 步的两位复核者也报了这一条，修复代理正在改。补法：
  - 脚本和 csc 源都直接 import 常量；`/out:` 和 procguard 路径由同一个函数算出，按相等比较，不接受回调，也不接受 fence 对象。

### 7.7 第 2b 步落地后学到的

复核又打出 5 个洞，都已补上，每处补丁都有变异见证。值得记下的是这几条事实：

- **锁只能随进程一起没。** 原来 stop() 只释放锁管道，而任何模块都能 `process.emit('SIGINT')`。再挂一个定时器，旧守护进程就没锁地活着，第二个实例照样进入 working，等于两个写者。现在停止就是退出进程，锁交给内核回收；生产代码里没有任何一行手动释放锁。这正是 P8：锁不是能被够到的东西，而是进程活着这件事本身。7.6 否掉「锁掉 emit」的理由仍然成立，不必锁 emit，让它无害就够了。
- **空原型的 init 挡不住 undici。** 在 24.22 上实测，fetch 的 RequestInit 转换对没有自有值的字段会顺着 Object.prototype 去读，dispatcher 也一样。所以 ports.fetch 每次都新造一个 init，每个字段都写成自有值，dispatcher 绑定死；调用方的 init 从不往下传。undici 的 globalOrigin 槽也锁空了，否则相对 URL 会被解析到模块指定的主机。
- **「在测试里」要从进程自己身上判断。** 注入的 env 可以不带标记，所以真实 profile 同时读进程自己的环境。测试里要跑真实 profile，只能走带类型的 opt-in，而且假 home 必须在临时目录的 orchestra-test-* 里。
- **退出码移到 20–29**，避开 Node 自己会用的 1、3–7、9、10、12–14。

留着的口子，已经记进第 3 步的简报：
- 直接 `node x.test.ts` 或 `--test-isolation=none` 时没有标记。这时进程内调 start() 又不覆盖 home，仍会跑真实 profile。打算加一条仓库测试：test/ 下每个进程内 start() 都必须固定 home，并传 IN_PROCESS_STOP。
