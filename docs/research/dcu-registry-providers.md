## Identity & scope

Key `registry-providers`. I read the two Cua Driver providers and the two name-only registries the way an integrator would who has to mount them into a private, headless DSH composition: the ACP app over dsh-base. Sources are the sparse clone of `deepseek-ai/deepseek-harness` at `22ddee3` (2026-10-23, `git log -1`), `npm view`, `gh api`, and the installed `@deepseek-ai/dsh` 0.2.1-rc.2. All paths are relative to the repo root unless marked `npm:` or `local:`. I ran no driver, installed nothing, and wrote nothing under G:/_Projects.

## Facts

**Registries**

1. `ctx.computerUse` and `ctx.browserUse` are the same 30-line class. One private `registration` field is held per Cordis service instance. `register()` throws if the field is already set, whatever the name. The effect disposer clears it (`packages/computer-use/computer-use/src/index.ts:16-46`, `packages/browser-use/browser-use/src/index.ts:16-46`). There are no tools, no Agent or Session keying and no lock. This confirms the ALREADY VERIFIED item.
2. The decision record rejected a "Session ownership broker". Concurrent Sessions remain "caller-coordinated" (`.agents/notes/implemented/architecture/2026-09-12-computer-use-provider-registration.md:19,29`). docs/subsystems/computer-use.md:35 says the same: callers coordinate observe/act/verify "across Sessions and separate DSH processes".
3. Exclusivity is per service instance, not per process or desktop. If `dsh-computer-use` were mounted per Agent scope, each Agent would get its own slot (inferred from the `Service` constructor in fact 1 plus Cordis service scoping). Two DSH processes always get independent slots (fact 2).

**MCP provider (`dsh-experimental-computer-use-cua-driver-mcp`)**

4. `inject = ['computerUse','tools']`. The config fields are `command` (default `cua-driver`), `args` (default `['mcp']`), `toolCallTimeoutMs` and `reconnect` (`packages/experimental/computer-use-cua-driver-mcp/src/index.ts:17-42`).
5. One effect does three things in order: it registers `cua-driver-mcp`, then runs `ctx.plugin(McpClient, {transport:'stdio', serverName:'cua-driver-mcp', failOnStartupError:true})` in the provider's own ctx, then yields `child.dispose`. Child teardown therefore finishes before the slot is released (`src/index.ts:53-70`). Because the client is mounted in the provider's ctx and not in `createScope(ctx, agent)`, its tools land wherever the provider entry sits (inferred from mcp.md:24,45 and contrasted in fact 20).
6. During a disconnect the registration is kept while the MCP client reconnects. The test `composition.spec.ts:168-185` proves that `register('replacement')` throws during the outage. The MCP client defaults are reconnect on, 500 ms → 30 s backoff and 10 attempts. After the budget is exhausted the tools are removed but the registration stays until unload (`packages/mcp/mcp-client/README.md:64-67,93`; provider README.md:53).
7. If initial connection or discovery fails, the Loader entry goes to FAILED and ownership is released after the child exits (`composition.spec.ts:187-200`).
8. README.md:114: "Sessions share one desktop… the registration does not serialize Session actions." The README also has no DSH permission UI or action abstraction (README.md:115).

**Native provider (`dsh-experimental-computer-use-cua-driver-native`)**

9. `inject = ['computerUse','tools','systemPrompt']` and `Config = {}`. It dynamically imports `@trycua/cua-driver` (exact pin `0.28.0`, `package.json:40`), calls `CuaDriver.create(undefined)` and parses `listToolsJson`. Tools are registered as `cua_driver_native__<name>` and must match `^[A-Za-z0-9_-]{1,64}$`. Each one is wrapped with `createMcpToolDefinition` (`src/index.ts:20-23,88-118`).
10. Cancellation is provider-owned. Each call uses `AbortSignal.any([execution.signal, lifetime.signal])` (`src/index.ts:110-113`). A `tools/execute` listener re-fuses the signal and tracks pending work (`:119-131`). On unload the provider aborts the lifetime, awaits pending calls, then runs `driver.shutdown()` and `uniffiDestroy()` before releasing the slot (`:59-78`). The decision record (`:19`) and README.md:132 state that delivered input is not rolled back.
11. If native shutdown fails, the slot stays occupied: "Restart the host before mounting another computer-use provider" (README.md:133; test `provider.spec.ts:219-228` asserts `providerName` stays `cua-driver-native` and re-register throws). The native runtime shares the host process, so a crash kills DSH (README.md:43).
12. The provider injects a fixed system-prompt section at `TOOL_COMPUTER_USE` order. Its text includes "Prefer background delivery. A refusal does not authorize a foreground retry" (`src/index.ts:37-41,132-136`).
13. There is no platform gate in either provider's source. Only the macOS `dsh-cua` row in cua-bundle is gated with `disabled: !!js process.platform !== 'darwin'` (`packages/experimental/cua-bundle/cordis.patch.yml:4-6`). So the Cua Driver providers are not darwin-restricted on the DSH side. Whether they work on Windows depends on upstream (not verified on this machine).
14. Registration is global, not per Agent. Neither provider references `agent`, `createScope` or `agentPresets` (whole files in facts 4 and 9). Contrast: `dsh-cua` (macOS) registers per Agent through `createScope(agent.ctx, agent)`, filtered by `agentPresets.composedPreset(...) === config.agentPreset` (`packages/experimental/cua/src/index.ts:349-375`). **Consequence: with the provider in the root composition, every Agent on that DSH host (every Musician) sees `mcp__cua-driver-mcp__*` / `cua_driver_native__*`, and concurrent calls are not queued (inferred from facts 5, 8 and 9).**

**Approval (Q1)**

15. The tool pipeline defaults `tools/pre-execute` to `{kind:'allow'}`. It reaches `ctx.approval.request` only when some listener returns `kind:'ask'` (`packages/core/tools/src/pipeline.ts:198-205,433-472`).
16. The generated consumer table lists the only `tools/pre-execute` listeners: `auto-review`, `hooks-claude-code`, `hooks-codex`, `tool-jobs` and `workspace-changes` (`docs/event-producer-consumer.md:81`). The only `kind:'ask'` producers in source are `auto-review` (`packages/experimental/auto-review/src/index.ts:701-708`) and the tools contract type (grep shown in-session).
17. **This changes the design note. Nothing classifies `cua_driver_native__*` or `mcp__cua-driver-mcp__*` as read vs write, and under the default `workspace-write`+`ask` preset desktop actions run with no approval prompt at all.** The `ask`/`never` policy only governs asks that something raises (approval.md:33). Presets bundle just the sandbox and approval knobs (permission-presets.md:5-11). (Inferred from facts 15 and 16; I did not run a live check.)
18. Auto review applies only when the session preset is `auto`. It reviews every call except a root `run_code`, and it sees tool name, arguments, schema and session history (`auto-review/src/index.ts:69,395-560,724-735`). A reviewer denial becomes `kind:'ask'`, which goes to the human (`:701-708`). I did not verify whether the reviewer sees screenshot images.
19. ACP forwards `approval/request` to the client as `session/request_permission`, and maps `allow-once` to `allowed-once` and anything else to `rejected` (`packages/acp/acp/src/index.ts:158-174`). It fires only when something asks (fact 15).

**Browser contrast and scope (Q4, Q6)**

20. `mountSessionMcp` does what the Cua providers do not. For each Agent, inside `agent/created` (prepend), it creates `createScope(ctx, agent)`, starts one MCP client with `reconnect:{enabled:false}` and `cwd` from `workingDirectory.ensure(agent)`, and denies calls from other Agents. It masks inherited tools for blocked Agents and strips the server's prompt section for non-owners (`packages/experimental/browser-use-runtime/src/mcp.ts:102-219`).
21. `SessionResources` keys by live `Agent` identity, never by durable id. It keeps one `ready` acquisition promise and one `tail` queue per Agent. `exclusive` means at most one entry, which is the attach mode. On disposal it aborts the controller and closes the resource before awaiting the tail. A failed close keeps the entry, which preserves exclusivity. Owner cleanup is an `agent.ctx.effect` (`browser-use-runtime/src/index.ts:60-197`). Playwright launch mode passes `--isolated` and `--headless`, defaulting to headless, while attach mode passes `--cdp-endpoint` with `exclusive:true` (`packages/experimental/browser-use-playwright-mcp/src/index.ts:35-50`; `mcp.ts:42-48`).
22. Shared-host-runtimes hazard: `dsh-scope` and `dsh-mcp-client` must be peers. If one is a dependency, npm installs a second copy whose scope tags the host ignores. Every Agent's tools then go global, and the second Agent's creation fails (`browser-use-runtime/README.md:86`; `tests/shared-host-runtimes.spec.ts:1-37`). A busy attachment is not retried during that activation (README.md:34,82). Browser state is not restored from the Session log (`docs/subsystems/browser-use.md:21`).
23. **Packaging hazard (from published npm metadata).** Both Cua providers declare `@deepseek-ai/dsh-mcp-client` as a regular dependency, not a peer (`npm view …cua-driver-mcp@0.2.1-rc.4 dependencies` returns `dsh-mcp-client 0.2.1-rc.4`; the native provider is the same). That is the edge fact 22 forbids for browser-use-runtime. Since these providers register globally anyway, the scope-tag failure does not apply. The live risk is version skew: the exact rc.4 mcp-client against host rc.2 peers (`dsh-mcp-client@0.2.1-rc.2` peers on `dsh-scope`, `dsh-tools`, `dsh-attachment` and others at exact `0.2.1-rc.2`, per `npm view`). Verdict: (inferred); I did not test an install.
24. npm `latest` for all five provider and registry packages is `0.1.6-alpha.1` (`npm view … dist-tags`), the version D#6788 reports as breaking profile boot. All of them also publish `0.2.1-rc.2`, which matches the installed host (`npm view …native@0.2.1-rc.2 version` → `0.2.1-rc.2`). Integrators must pin exact versions and never use `latest`.
25. `scripts/package-dependency-policy.ts:53-62` lists `@deepseek-ai/dsh-computer-use/brand: ['ComputerUseProviderName']` in `SAFE_HOST_DEPENDENCY_EXPORTS`. That is a reviewed list of exports that stay valid under duplicate installs, not a publication allowlist. Publication is now default-public for every `packages/experimental/*` (`scripts/experimental-package-policy.ts:64-80`, `PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES = []`). **This contradicts the decision record's "explicit public-release allowlist" wording (`2026-09-12-computer-use-provider-registration.md:15,33`); the record is stale (inferred).**

**structuredContent (Q2)**

26. The canonical value keeps `structuredContent` (`packages/mcp/mcp-client/src/tools.ts:301-306`), and tests assert it (`computer-use-cua-driver-native/tests/loader-composition.spec.ts:128`; `mcp-client/tests/tool-definition.spec.ts:41`). **But the Native-mode model projection is `render()` → `extractText(result.content)`, and `projectContent` never reads `structuredContent` (`tools.ts:250-266,449-511`).** The model therefore sees structuredContent only through PTC code (`McpResult` "exposed to PTC mode", `tools.ts:38-42`). D#7788 is still open (`gh api graphql`, `closed:false`). This confirms the D#7788 drop for Native mode at HEAD and partly contradicts the "whether fixed is NOT verified" item: it is not fixed at HEAD.
27. Upstream cua-driver keeps action truth in `structuredContent`: `effect`, `route`, `delivery.mode`, `snapshot_id`, `degraded`, and `tree_markdown` for daemon-proxied responses. The text may carry only a summary (`trycua/cua@cua-driver-rs-v0.28.0:libs/cua-driver/rust/crates/cua-driver-testkit/src/response.rs:7-8,57-112`). So a Native-mode DSH model cannot see whether an action was delivered in the background or the foreground. I did not verify whether `element_token` also appears in text.

**ACP path (Q5)**

28. ACP `session/new` takes per-session stdio and HTTP MCP servers, each with an absolute command. They are mounted with `agentCtx.plugin(McpClient, …)` in the unpublished Agent scope, with `failOnStartupError:true` and `cwd` set to the session cwd (`packages/acp/acp/src/mcp.ts:20-73`; `README.md:66,82`). So `cua-driver mcp` can be attached per Musician without either DSH provider or registry: Agent-scoped tools, but no exclusivity at all (inferred from facts 1 and 28).
29. Installed `dsh-acp-app` patch: system-prompt persona, `session-title-llm` disabled, `dsh-acp` with `deepseek-official/deepseek-v4-flash`, `hmr` disabled (`local: …/dsh-acp-app/cordis.patch.yml:3-23`). It adds no computer-use rows. ACP admits images only with a durable attachment store and an image-capable route (`packages/acp/acp/README.md:64,175`).
30. The minimal working composition the tests prove (`computer-use-cua-driver-mcp/tests/composition.spec.ts:62-86`) is these rows: `dsh-computer-use`, `dsh-system-prompt`, `dsh-tools`, `dsh-tool-executor-native`, `dsh-llm` plus an adapter whose `resolveModel` returns `inputModalities:['text','image']`, `dsh-session`, `dsh-agent`, `dsh-agent-loop {agents:[]}`, `dsh-session-projection`, `dsh-attachment-local {dshHome}`, and the provider. Without an attachment store or a declared image route, screenshots become the text `[image unavailable: …]` (`tools.ts:352-379`). The native provider additionally requires `systemPrompt` (fact 9).

## Patterns for Orchestra

- **Adopt the browser-use-runtime ownership model for desktop leases (facts 20-22).** Key by live Agent identity, keep one acquisition promise and one FIFO per resource, close before draining, keep the reservation when close fails, and use `exclusive` for anything that is one physical thing. A desktop is the `attach` case, and DSH already wrote the semantics, but only for browsers.
- **Do not rely on `dsh-computer-use` for exclusion (facts 1-3, 8, 14).** It is a composition lint that stops two providers being mounted. It is not a Session lease. The Orchestra Lease and Grant (E-rules) must live in Orchestra / Post Office, above DSH.
- **Gate desktop tools yourself (facts 15-19).** Under the default preset the tools run unprompted. Orchestra must either (a) attach the driver per Musician through ACP `mcpServers` (fact 28) and only while a human-granted Lease exists, or (b) install a `tools/pre-execute` listener (for example through `hooks-claude-code`/`hooks-codex` style hooks, not verified) that returns `ask` for the Cua namespaces, so ACP turns it into `session/request_permission` for a human (D8). Do not treat Auto review as the approver: it is an LLM, it applies only under the `auto` preset, and D8 requires human-only approval.
- **Prefer the MCP provider or the ACP-attached `cua-driver mcp` over native (facts 10-11).** A native crash or failed shutdown takes down the host or wedges the slot until restart, which is incompatible with Musician hosts that must survive.
- **Run Musicians that use desktop tools in PTC mode, or carry structuredContent yourself (facts 26-27).** Otherwise the Musician cannot see `effect`/`route`/`delivery.mode`, cannot verify background vs foreground delivery, and may lose `element_token`.
- **Pin exact package versions that match the host (facts 23-24).** Never install `latest` (0.1.6-alpha.1). Expect peer-skew trouble from the providers' `dsh-mcp-client` dependency edge.
- **Use per-Musician isolated browsers from DSH directly for Tier 0 (facts 20-21).** Playwright MCP in `launch` mode with `--isolated --headless` already gives a per-Agent browser in that Agent's scope. Orchestra needs no new code for this, apart from the peer-dependency install hazard (fact 22).

## Verdict

Partly. A headless ACP Musician can mount `dsh-computer-use` plus the MCP or native Cua Driver provider today if it pins `0.2.1-rc.2` and adds an attachment store and an image-declaring route (facts 24, 30). These breaks are confirmed in source:
- The tools are global to the DSH host, so every Musician sees them, with no per-Session queue or lease (facts 5, 8, 14).
- They run with no approval prompt under the default preset (fact 17).
- Native mode hides the driver's `structuredContent` truth fields (facts 26-27).
- Native failures can kill the host or wedge the slot until restart (fact 11).

The cleaner path today skips DSH's providers entirely. Attach `cua-driver mcp` per Musician through ACP `session/new.mcpServers` (Agent-scoped, fact 28), with Orchestra owning the human Lease and approval gate. The "no Tier 2 driver yet" line in the design note should change to: "an upstream driver exists and is mountable, but DSH supplies no lease, no approval classification and no per-Session isolation for it."
