# 乌龟塔面板调研报告

## 结论

我推荐用**塔表**做新面板的骨架：首屏是一张三层树表，从上到下是你（路由层）→ agent → subagent，每一行格式相同，都能就地展开、单独停下。树的上方钉一条「等你」栏，按离超时的远近排。这个方向在三位评审的打分里总分最高（塔表 156，收件箱 148，DSH 原生 134，工单台 118）。另外三个方向里的好做法也嫁接了进来：收件箱的分组和计数筛选、工单台的派活存根、DSH 原生方向的「按钮写明在哪儿执行」和插件数据通道。

装进 DSH 的方式：**主界面仍是 orchestrad 自己的页面，DSH 里做一个独立的只读插件**，左栏放一个图标，主区放一整页只读塔表。不做 BSB tab（BSB 即 DSH-better-sidebar，第三方右侧栏插件）。所有批准、拒绝和停止都跳回 Orchestra 处理。

最快能看到东西的第一步：先用现有的只读接口在真实数据上抽样一次，量出 subagent 能挂到 agent 下面的比例。确认树能长出来之后，再画只读塔表。

- 全程只读，没有改仓库、没装包、没启动 DSH 或 orchestrad。
- 网页抓取有几轮失败（WebFetch 报 Socket is closed），所以部分网上来源只看到了搜索摘要，都已标明。

## 1. 推荐方案：塔表

### 1.1 首屏回答三个问题，从上往下排

1. **谁在等我，还剩多久。** 钉栏只收三类事：审批、提问、派给谁（Route to?）。这对应 r4 §11.2 首页的「需要你」组（r4:2073-2077）。
2. **整座塔现在什么样，卡在哪。** 同一层的节点按「等你 > 出错 > 在跑 > 等别的 agent > 已回报 > 空闲」排。
3. **我选中的这一行在干什么，我能对它做什么。** 右栏的详情、底部的输入框和停止键，都绑定到选中的那一行。

### 1.2 页面清单

| 页面 | 作用 | 对应 r4 |
|---|---|---|
| **塔（首页）** | 「等你」钉栏 + 跨项目树表 + 右栏详情 | 合并了 Program 首页（r4:2058）和 Stage 舞台图里「谁派了谁」的部分（r4:2060） |
| **乐手页** | 单个 agent：左边只显示它这一枝，中间是对话，右边是选中的 subagent | r4 §11.7 乐手页（r4:2204） |
| **派单记录** | 每次派活的 RouteDecision（一次派活决策的记录：候选、拒绝码、理由、模式，r4:649） | M1 起记手动派活，M4 起加入 Maestro 的建议 |
| **关于数据** | 源健康、判定规则的样本数、哪些关联是推测的、诚实声明全文 | 落实呈现原则「健康状态不占空间」（r4:2110） |
| **设置** | 打扰档位、live profile 的 opt-in、配对和解锁 | — |

alpha 的问题之一是一页干两件事、诚实说明铺满主画面。这里的改法是：主画面只放「谁、在做什么、等不等你」，其余都进详情或「关于数据」页。

### 1.3 三层怎么画

所有层共用一种行格式，层级只靠缩进和行首竖线区分：

```
[状态图标] 名字 · 派活存根 · 一句当前活动/在等什么 · 子节点小框 · 时长 · 归属
```

- **第 0 层：路由（superagent）。**
  - M0（只读注意力层，只观察不驱动）时，这一行只写「◆ 你」，没有输入框。
  - M1–M3 时，这一行是「◆ 你 · 派活台」，带派活输入框，按钮永远是「派出」，不会变成「停止」。这一层在 r4 里由你，加上你指定的一个自有乐手当主代理（r4:293）。
  - M4 起这一行换成 Maestro（只做路由、从不改代码的自有乐手，r4:1475）。
  - **M4 之前不画任何假的路由大脑。**
- **第 1 层：agent。** 对应 r4 的「乐手」（固定名字的持久身份）或一个根会话，一行一个。行首 3px 竖条是 harness 的颜色。每行带归属徽标：自有 / 只读 / 被占用，对应 D4（会话三类归属，Orchestra 只驱动自己创建的，r4:490）。
  - 行上的**派活存根**取自工单台方向：有派活记录时写实线的「你派 · 10:42」，点开就是那条 RouteDecision；从会话推断出来的写虚线「推出」。这样路由层在 M4 之前也有一个诚实的落点。
- **第 2 层：subagent。** 对应 r4 的「分身」（原生 subagent 或 DSH 队友，r4:642）。它缩进挂在父行下面，列和 agent 行完全一样。

**子节点小框** `3·0·1✋` 依次是：子节点数、其中出错数、其中等你数。等你的数量会沿祖先链一路往上加，这样不展开也能知道哪一枝在等你。这个做法借自 Honeycomb 的后代计数框。

**折叠规则**照搬 BSB 和 Claude agent teams：
- 在跑、等你、出错、选中的、有子节点的行，永远不折叠（`$BSB\src\client\tasks-model.ts:207-235`）。
- 已回报的叶子合成一行「已回报 ×N」。
- 空闲的满 3 个才合成一行。
- 同类大批 subagent 合成一行，例如「×12 Explore · 9 已回报」，借自 Langfuse 的聚合模式。

### 1.4 subagent 作为一等公民，具体落在哪

| 能力 | 做法 | 依据和限制 |
|---|---|---|
| 单独一行 | 和 agent 行用同一套列，有自己的图标、活动、子节点小框 | r4 的分身实体本身带 `status / depth / parentCloneId`（r4:642） |
| 就地看一眼（peek） | 按 Space 原地展开：它在问什么、最后一句话、合并后的工具活动（如「Read ×12」）、回报摘要 | 回报遵守 A16（薄完成：只带状态、有界摘要和引用，截断要标出来，`docs/research/zen-superagent-spawn-overview.md:90`） |
| 单独打开 | 按 Enter 进入乐手页，右栏是它的完整记录。DSH 的 subagent 也可以打开 DSH 原生的子代理对话 | 地址精确到父子对（`$N\dsh-client-ui-subagent\README.md:28`） |
| 单独停下 | 「停这棵子树」：确认框先列出会停掉的全部后代，停完回报「已停 3 个，1 个无响应」 | Claude 用 `stopTask()`，DSH 用 `interruptByParent`（r4:1595）。**S2 清单第 ④ 项「中断单个分身」还没实测**（r4:2414），实测前按钮旁标「未验证」 |
| 上下文用量 | 只放在详情里。DSH 用每个子会话的 `tokenUsage`（`$N\dsh-client-ui-subagent\README.md:66`）；拿不到的写「未知」，不写 0 | r4 的分身实体**没有这个字段**（r4:642），需要补 |
| 「等你」冒泡 | 审批卡写出完整来源路径「你 › alpha › explore-2」，分身行和父行同时亮起 | DSH 的 subagent 审批被钉成「永不」，需要审批的操作会被自动拒绝（`$N\dsh-subagent\lib\index.js:397-415`），所以这类情况只在「出错」组显示「被自动拒绝 1 次」。Claude 后台 subagent 的审批会冒到主会话（code.claude.com 工具参考页，**未核实**） |
| 对它说话 | 默认发给它的父 agent，并注明「话题：explore-2」。能不能直接对它说，**等你拍板**（第 6 节第 1 条） | D2 / D14 |

### 1.5 关键交互

**选中即上下文。** 这条借自 VS Code 调试器的调用栈：选中哪一行，右栏详情、底部输入框、停止键就作用于哪一行。输入框上方永远写「发给 → X」。开始打字后目标就锁住，树再怎么变也不改收件人。

**批准和拒绝。** 只对自有会话有效，遵守 D8（只有一个审批队列，超时即拒；审批、拍板、刹车只能由你在配对过的 Orchestra 页面上做，r4:494）。
- 钉栏上**只放「拒绝」和「审…」，不放「允许」**。完整审批卡固定显示在**右栏**，不在树行里展开，避免树重排时点错位置。
- 审批卡沿用 0.2 的设计（0.2 设计 :215-234）：
  - 参数全文显示，不可见字符转义成可见形式。
  - 默认焦点在「不允许」上，显示倒计时「剩 mm:ss 自动拒」。
  - 批准时要带上参数摘要和页面看到的列表版本；服务端说页面过期就重画。
- 防误触按 r4:1669-1670：列表一变化，所有「允许」灰 750 ms；shell、网络、受保护路径这类高风险操作要长按或键入确认。
- **不做批量审批**（r4:1678）。
- **两种「等你」分开标：**
  - Orchestra 队列里的：写「剩 27:40 自动拒」。
  - 只读会话推测出来的：写「≈ 可能在等你」，**不显示工具名和参数**，只给「去原生界面 ↗」。这是因为只读会话的等你只能靠低置信推测（r4:825），DSH 原生审批也没有计时器（`$N\dsh-user-approval\lib\index.js:176`）。

**发消息。** 默认「排在这一轮之后」（queue），「插进当前回合」（steer）是下拉里的第二项（r4:2204）。只读会话的行没有输入框。

**停止分三档**，位置、颜色、确认方式都分开：
1. **停下这一轮**：只作用于选中节点。中断是人类专属，见 D15（权威类型只用一个 `trust` 字段，中断只能由人做，r4:501）。
2. **停这棵子树**（键 `s`）：先列名单，停完给回执。这是吸取 Claude 桌面版的反例：用户报告停一个 agent 不会连带停它的子 agent（claudeissues #74844，**未核实**）。
3. **刹车 K**：kill-tree，在顶栏右侧，两步确认，第一次点后 3 秒内再点才生效（照 `$BSB\src\client\JobsDrawer.tsx:40-41`）。只读会话**只有**这一个写操作（r4:1548）。

**每个按钮写明在哪儿执行**，例如「在 Orchestra 里停下 ↗」「在 DSH 里打开 ↗」。按钮背后是一张「归属 × harness × 层级」的能力矩阵，写成纯函数，同一个按钮不会在不同行里暗地做不同的事。

**导入和交还原生。** 都放在行的「⋯」菜单里。导入沿用 0.2 设计（resume / fork / DSH 快照，0.2 设计 :450-459），按你 2026-11-02 的决定，导入的会话**不**默认算污染：工作目录内的只读工具不每次问，行上只标「导入的」。（调研子代理照 0.2 设计稿原推荐写成了「每次都问」，这里已改正。）交还原生后这一行降为只读（r4:2211）。

**实时更新不打扰。**
- 推送走 SSE，这是 D3 已定的（D3：只有一个守护进程 orchestrad，网页只在 `orchestra.localhost` 上提供，r4:489）。
- 鼠标或焦点在树里时冻结排序，变化攒成一个小签「↻ 4 处变化」；你停手 5 秒后才重排。
- 只有状态词变化时，行底色淡亮 1.2 秒。活动文字原地覆盖，不堆日志。
- 返回的数据逐字段比较，没变化就不重渲染（照 `$BSB\src\client\SubagentView.tsx:84-160`）。
- 数据陈旧时只把顶栏的圆点变灰并写秒数，**不让整片变灰**。alpha 的教训是整片变灰时「等你」也跟着褪了色（alpha `ui/stage.css:75`）。
- 读屏只播报「等你」数量的增减。浏览器标签页标题写「(2) Orchestra」。

**诚实规则怎么落。** T1–T8 是 alpha 0.1 设计稿里的八条诚实规则：
- T1（每个标记都对应一个字段，否则写未知）、T2（界面不出现「完成」）、T3（每个计数等于它链接的列表长度）：留在主画面。顶栏计数和钉栏计数点开就是同一个列表。
- T4（没在真实样本上测过就写「未测（N=0）」）、T6（源健康只在出错时出现）：挪到「关于数据」页。
- 推测出来的状态在名字后面加一个淡色的 `≈`，依据放进详情，不再像 alpha 那样每个状态后面都括号带依据。

## 3. 视觉方向：「航图」

整页像一张冷灰的图纸，靠细线、缩进和三种信号色说话。不用阴影卡片堆，不用全大写小标签，不用奶油底配赤陶色，也不用黑底配荧光绿。

**一色一义。** 这是开眼准则 P1「一符一义」的落地（`docs/research/2026-10-31-eye-diagram-zen.md:18-21`）。CSS lint 锁死：黄只给「等你」，朱只给「出错」。alpha 的教训是琥珀色被挪去标了一堆别的东西（alpha `ui/stage.css:3-4` 定了规矩却没守住）。

| 名称 | 用途 | 亮色 | 暗色 |

## 4. 装进 DSH

### 4.1 选哪种装法

**独立 DSH 插件，只读，挂在官方的全局槽位上**：

| 位置 | 放什么 |
|---|---|
| 左栏 `sidebar.panellist` | 一个「塔」图标，有等你时亮一个黄点（借 dsh-sentinel） |
| 主区 `main` | 只读塔表：钉栏 + 树，**去掉派活台和底部输入框** |
| 输入框上方 `conversation.input.dock` | 可选，一条「等你 N · 最急：…」带，没有事就不渲染 |
| 会话头 | 「在 Orchestra 打开 ↗」 |

左栏图标加主区整页，正是 DSH 官方「定时任务」插件自己用的形态（`$N\dsh-client-ui-schedule\lib\client.js:7473-7491`，已核对）。

**不做 BSB tab，有两个原因：**
1. 右栏标签页按会话划分，装不下跨会话的第 0 层（`$N\dsh-client-ui-sidebar-right\lib\types\client\contract\slots.d.ts:37-39`）。
2. BSB 会把一整套只靠 Host/Origin 围栏保护的写路由带进宿主：作者自己写明那道围栏「不是鉴权」（`$BSB\src\trust-fence.ts:10`），文件系统路由也不检查是否在工作区内（`$BSB\README_ZH.md:193`）。

### 4.2 数据和审批权怎么走

```
DSH 页面（浏览器）
   │  ctx.connection.fetch（DSH cookie 鉴权，不是 owner 得到 403）
   ▼
插件宿主一侧 ── 只读 GET token（只放在宿主内存里），走回环地址 ──► orchestrad
   │  WebSocket 只推「数据版本变了」的信号，不带数据
   ▼
浏览器收到信号后再拉一次
```

- **token 不进浏览器。** 同一页面里所有插件同源运行，token 放在浏览器里，任何插件都读得到。r4 本来就规定给私有控制台单发一个只读 token、不共享 UI cookie（r4:2265）。
- 浏览器到插件宿主走 `ctx.connection.fetch`，它用 DSH 的会话 cookie 鉴权，不是 owner 的连接拿到 403（`$N\dsh-client-connection\README.md:49`）。不学 BSB 的「裸路由加围栏」。
- WebSocket 用 `ctx.webServer.registerUpgrade` 开（BSB 先例：`$BSB\src\index.ts:1744-1756`），只推信号，所以即使它没鉴权也泄露不了内容。
- 插件和 orchestrad 自托管页面**共用同一份纯函数 view-model 和契约校验器**，两边计数不会对不上（T3）。
- **审批权只在 orchestrad 的配对页面。** DSH 镜像里所有 ✋ 和 ？ 都是「去 Orchestra 处理 ↗」。DSH 自己的原生审批卡仍由 DSH 自带的 `ui-approval` 处理，插件**不监听也不观察** `approval/request`。
- **安装顺序：**
  1. 先装在私有 DSH 控制台。私有控制台是 Orchestra 私有 home 上跑的 `dsh web --port 3199`，计划在 M2，可选（r4:2265）。
  2. 你平时用的 live web profile 走 Q5a（默认不放 Orchestra 代码，你主动开启后只加载只读部分，r4:2923）。
  3. 所有 bundle 都先在隔离的 `DSH_HOME` 上验证，这是 D11（只对接、不魔改，r4:497）的要求。

## 6. 被放弃的方向

- **收件箱 + 下钻**（148 分）：一眼看懂最强，但塔的形状要点进去才看得到，交付的不是乌龟塔看板。它的分组顺序和「计数即筛选」已经嫁接进钉栏和顶栏。
- **工单台**（118 分）：前提是「一件事」这个单位存在，可只读会话里根本没有任务实体。一个会话硬算一张工单会违反 T1；M0 时「待派」列恒为空，看板会退化成会话列表。它的派活存根已经嫁接。
- **DSH 原生优先**（134 分）：要改 D3，主场私有控制台要到 M2 才有。Claude 会话每个动作都要跳出去，主力会话反而成了二等公民。挂在 DSH 审批链里的观察者一旦漏传下去，审批就会挂住。它的「按钮写明在哪儿执行」和插件数据通道已经嫁接。

## 8. 第一个薄切片

1. **真实数据抽样。** 用现有的 `GET /api/peek/stage`（alpha-0-2 `src/server/http.ts:331`）在真实会话上只读跑一次，输出三个数：subagent 能挂到父节点的比例、并发会话数、最大深度。
   - **看得见的结果：** 一张小表。这三个数决定树能不能长出来。0.1 的 13 条判定规则在真实数据上样本数都是 0，交接文件也预计会大量显示「未关联」（`alpha-0-1/docs/handoff/claude--alpha-0.1.md:29`）。
2. **写 TowerSnapshot 契约和纯函数 view-model。** 从 0.1 的 `stage-contract.js` 改名扩字段：层级、逻辑父 ID、派活存根、`waiting.source`（orchestra / dsh-native / 推测）加置信度、能力矩阵。沿用 `groupPlayers` / `handedOn`（alpha-0-1 `ui/layout.js:59-98`）和 T2、T3 的金样本测试。
   - **看得见的结果：** 合成数据和真实数据都能通过校验器，测试是绿的。
3. **在 `orchestra.localhost` 上做只读塔表。** 包括钉栏（M0 时只会出现「≈ 可能在等你」）、树、右栏详情、折叠和聚合、SSE 加排序冻结。
   - **看得见的结果：** 用真实数据打开浏览器，一屏看到你所有 Claude 和 DSH 会话，以及它们的 subagent。
4. **「关于数据」页。** 把诚实声明、「未测（N=0）」、源健康从主画面撤到这里。
   - **看得见的结果：** 主画面只剩「谁、在做什么、等不等你」。
5. **（M1）把 0.2 的交互接上塔表。** 等 0.2 会话做完后端步骤（POST 底座、驱动、审批、接口；调研时它正在改 `shared/protocol.js`、`src/server/routes.ts`、`src/server/http.ts`，还没提交），再接右栏审批卡、「发给 → X」输入框和三档停止。
   - **看得见的结果：** 对一个自有 Claude 会话，在塔里批准、发消息、停下一棵子树。
6. **DSH 只读插件。** 在隔离的 `DSH_HOME`（3099 端口）里先装：panellist 加 main，宿主一侧持有只读 token。
   - **看得见的结果：** 在 DSH 左栏点「塔」，看到同一棵树，计数和 orchestrad 页面一致。

## 第一步结果：真实数据抽样（2026-11-02）

做法：用 alpha-0.1（eead531）的 orchestrad 以真实模式只读运行一次，数据目录指到临时目录，取一次 `/api/peek/stage`，只统计数字，没有保存或展示会话正文。

| 指标 | 数字 | 说明 |
|---|---|---|
| Claude 会话 | 60 个进了快照，其中 13 个在 registry 里（活着） | 60 是快照上限 |
| 此刻在忙的 | 4 个主会话（3 个 busy，1 个 waiting），subagent 0 个被确认在跑 | 状态来自 registry |
| 画出来的成员 | 135 个：24 个主会话 + 111 个 subagent；另有 718 个因上限被裁掉 | 裁掉的比画出来的多 5 倍 |
| subagent 挂到上级 agent | 111/111（100%） | 靠文件位置，必然挂得上 |
| subagent 挂到「哪一次派活」 | 2/111（2%），靠 agentId | 其余 109 个只知道属于谁，不知道是哪条 Task 派的 |
| subagent 的运行状态 | 109/111 是「未知」 | registry 只管主会话 |
| 最大深度 | 1（主会话 → subagent） | 画出来的部分里没见到第三层 |
| 一个主会话最多的 subagent | 16 个 | 需要「×N 已回报」聚合 |
| DSH | 显示「没有会话」，实际磁盘上有 92 个 | **诚实规则的 bug**，见下 |

**发现的 bug：** 快照按「最新 60 个」截取，再按 harness 计数。你最近 Claude 用得多，60 个名额全被 Claude 占了，DSH 的 92 个会话（最新的是 10-23）一个也没进，来源状态却写成「empty（没有会话）」。这违反 T1（不知道要写不知道，不能写成没有）。修法：来源计数用截取前的总数，界面写「92 个，因上限未显示」，或者按 harness 分配名额。代码位置：alpha-0-1 `src/sources/stage.ts:1057-1060`、`src/sources/peek.ts:152`。

**对塔表设计的影响：**
1. 树能长出来，但只有两层：「你 → 主会话 → subagent」。第三层（subagent 再派 subagent）在真实数据里暂时没有，设计照留，不优先。
2. subagent 的状态绝大多数是「未知」：塔表上 subagent 行默认要写「状态未知」，不能画成在跑或空闲；需要补 subagent 的活跃判定（例如按文件最近写入时间，标「推测」）。
3. 派活存根只有 2% 能对上：「你派 · 10:42 → 哪个 subagent」这种连线大多画不出来，先只画「属于谁」。
4. 一个主会话下最多 16 个 subagent，裁掉的有 718 个：聚合（「已回报 ×N」「×12 Explore」）和「只看最近」是必需的，不是锦上添花。
