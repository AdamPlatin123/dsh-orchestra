# 第二轮简报：总台问答、worker 派发清晰、subagent 默认折叠（2026-11-03）

第一轮 14 个方案比的是隐喻。第二轮只比一件事：**怎么一层层看下去，又不乱**。

共用的上下文仍然是上一级目录的 `BRIEF.md`：第 1 节（现有前端错在哪）、第 3、4 节（第一性原理和 P1–P12）、第 6 节（反模式）、第 8 节（界面用语）继续有效。本文有冲突的地方，以本文为准。

## 1. 用户的三条判断（本轮的硬约束）

用户原话：「superrouter 应当尽一切可能避免自己做任何非问答式的工作，worker 派发 subagent 应当尽可能清晰，到 subagent 层级就应该默认像 Claude Desktop 一样折叠了」。

| 编号 | 规则 | 落到界面上 |
|---|---|---|
| **F1** | **总台只问答。** 总台（superrouter，r4 里最接近的是 Maestro）只做三件事：回答你、把活派出去、把回报转成一句话。 | 总台的对话里只有四种东西：你的话、它的回答、派单回执、回报摘要。这里永远看不到工具调用、diff、日志。查 Orchestra 自己的状态算问答。回答要标出处（`sources`）。 |
| **F2** | **派发必须一眼看清。** 每一次派发都是一个看得见的对象，不是对话里的一句话。 | 派单写清五件事：**派给谁、做什么、为什么、要交回什么、现在怎样**。worker 派 subagent 也一样（数据在 `dispatch` 字段）。扫一眼 worker，就要能读出它把活拆给了谁。 |
| **F3** | **subagent 默认折叠。** 像 Claude Desktop 的工具调用块：一行摘要，点开才有内容。 | 折叠行只写：名字或组名、分项计数、耗时或状态。默认不展开，运行中也不自动展开。更深的 subagent 是折叠里的折叠。subagent 没有输入框（r4 D2：分身不能收消息）。 |

**F3 的唯一例外，也是本轮最重要的一条：折叠不能藏事。** 等你的事和出错的事永远冒到顶层（P3），折叠行上同时带一个小标记。其它状态变化都不能把折叠行撑开。

### 1.1 折叠卡的样子（用户给了截图）

用户原话：「折叠类似这样，允许点击以查看一些细节」。截图是 Claude Desktop 的工作流卡：第一行名字，右侧一个箭头；第二行「Workflow · 6 agents · 7s」；第三行一排小点，一个 agent 一个点。

- 所有 subagent 折叠块都用这张卡，用共用的 `foldcard.js` 和 `kit.css` 里的 `.fold`，不各写一份。
- 第二行固定写类型、数量、耗时。耗时不知道时写「耗时未知」，不留空。
- 第三行的点数等于成员数（T3）。颜色：蓝 = 已回报，绿 = 在跑，黄 = 等你，红 = 出错，灰 = 有记录（抽样没给具体状态），空心 = ≈ 推测，虚线 = 状态未知。
- 超过 16 个成员时，点换成按比例的分段条，卡的高度不变（P1：成员从 12 个涨到 120 个，首屏不变）。
- 点卡片展开细节，箭头转向下。展开后才出现成员列表。

### 1.2 规划交给 worker（用户 2026-11-03 拍板）

总台不写验收、不拆 Task。这些归一个专门的规划 worker（数据里是 Sora）。

- **总台还能做的：** 提议「这件活派给谁」。这是路由，属于 F1 的「把活派出去」。默认你点「派出」才算数；用户 2026-11-03 又要求可以开权限让 bot 直接派出，见 `../round3/BRIEF.md` 第 1.1 节。第二轮的 6 个方案没有加这个权限。
- **规划 worker 做的：** 写验收条款和 Task 列表，提议改计划。提议由你拍板。
- **规划 worker 不做的：** 不接 Task，不判定是否通过（r4 §8.9 (c)）。
- **和 r4 的差别：** r4 §8.9 (c) 写规划者是主代理（M1–M3），M4 起可为 Maestro。这次决定把规划从总台拿走，r4 这两处还没改，改不改由用户决定。

## 2. 逐层查看的阶梯

每点一次只多看一层，不跳层：

1. 一句话（总台的回答，或顶层的状态条）
2. 派单（F2 的五件事）
3. worker 的对话（它说了什么，派了谁）
4. subagent 折叠行展开成成员列表
5. 单个 subagent 的派单和步骤（工具调用，同样一行一步）
6. 原始记录（占位即可，写明在哪）

**层与层用同一种语法。** 用户学会一次「点开一行」，往下五层都一样。

## 5. 硬性要求

- 单个自包含 HTML：`round2/NN-<短名>.html`。必须引用 `kit.css` 和 `scenario2.js`，所有内容从 `window.R2` 渲染，不在页面里另写一份数据。不引用任何外部资源。
- 用 `kit.css` 的变量和字体，不另起配色。本轮比结构，配色统一才比得出来。可以有自己的布局和动效。
- 界面主文案用用户的词：**总台、worker、subagent**，其余按上级 `BRIEF.md` 第 8 节。全页不出现「完成」「Done」和 ✓ 打勾状态。
- 计数等于点开后的列表长度，分项之和等于总数（T3）。未知不画成空闲或 0（T1）。只读会话上不出现批准、发消息、中断。不做批量批准。
- 1024 px 宽无横向滚动，1280–1600 是主宽度。浅色、深色都能读。右上角放深浅切换和「设想 / 今天」开关。
- 页面角落放一个可折叠的「设计说明」，写：这个方案怎么回答「不乱又能看下去」；三条规则各怎么落地；自己最弱的一点。
- 左上角放「返回第二轮」链接，指向 `index.html`。
- 不要做头像墙、聊天墙、无限缩进树、假忙碌动效。
