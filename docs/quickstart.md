# Orchestra 上手指南（2026-11-03 更新，分支 claude/orchestra-app）

写给 Orchestra 的主人：怎么启动、怎么配对、页面上每块是什么、哪些能操作、哪些只能看、现在还有哪些已知的限制。

**代码在哪。** 本文说的功能（自有会话、派活台、刹车、DSH 请求卡）目前只在一个 git worktree 里：`G:\_Projects\dsh-orchestra\.claude\worktrees\zen-superagent-exploration-04992d`，分支 `claude/orchestra-app`。这条分支**没合并、没 push**，远端没有它。主检出目录 `G:\_Projects\dsh-orchestra` 上的 `main` 还没有这些功能。自有 Claude 会话要用的 `hosts\claude\node_modules` 也只在这个 worktree 里有。所以下面的命令都在这个 worktree 的根目录里运行。

先说几个词：

- **orchestrad**：Orchestra 的后台进程（守护进程）。页面只是它的窗口，关掉页面它照样在跑。
- **观察到的会话**：Claude、DSH、Codex 自己开的会话。Orchestra 只读它们的记录文件，不驱动、不批准、不停止它们。
- **自有会话**：Orchestra 自己开的 Codex 或 Claude 会话。只有这种会话能在页面上发消息、审批、停下。
- **magpie**：本机的模型网关 `http://127.0.0.1:3425`，不需要密钥。自有会话和派活台的路由模型都走它。
- **数据目录（ORCHESTRA_HOME）**：真实数据默认放在你用户目录下的 `.orchestra` 文件夹（`%USERPROFILE%\.orchestra`，即 `~/.orchestra`）。设了环境变量 `ORCHESTRA_HOME` 就用它指定的位置。

## 1. 启动

### 1.1 用你的真实数据启动

**最省事的办法：双击仓库根目录的 `start-orchestra.cmd`。** 它在一个看得见的控制台窗口里运行下面这条命令，大约 5 秒后用默认浏览器打开 `http://orchestra.localhost:7470/`：

- **由你双击，不开机自启、不进计划任务、不由别的程序启动。** 原因是代-2（M0 计划 `docs/plans/2026-10-31-m0-implementation-plan.md` 第 200 行：真实 profile 只由你在可见控制台里用 `orchestra.cmd` 启动，不开机自启；配对码只在 stdin 和 stdout 都是控制台时打印；agent 只许起测试 profile）。
- **配对码只在启动后 10 分钟内有效**，只能配一个浏览器。错过了就在那个窗口按 Ctrl+C，再双击一次。
- **重启会丢东西**：自有会话的对话内容只在 orchestrad 的内存里，重启后看不到（没结束的会话显示「状态未知」）；还在等你的 DSH 请求也一起丢掉，DSH 那边再查会报错。
- 它自己找 node：没设 `ORCHESTRA_NODE`、旁边也没有 `.tools\node24\node.exe` 时（worktree 就是这样），用主检出目录的 `.tools\node24\node.exe`（worktree 往上三级）。
- 额外参数原样传给 orchestrad，例如 `start-orchestra.cmd --test-profile --test-dir %TEMP%\orchestra-test-x` 用合成数据（见 1.2），`start-orchestra.cmd --project-root D:\code\shop` 让自有会话能在你的项目目录里干活（见 1.3）。再给一个 `--peek-port` 会被拒绝（重复参数）。`start-orchestra.cmd /dry-run` 只打印它会运行什么，不启动任何东西。
- orchestrad 退出后窗口停在「按任意键继续」，方便你看退出原因。
- 脚本里的注释是英文的：cmd 按控制台代码页读 .cmd 文件，里面的 UTF-8 中文可能把前后几行读坏。

不用脚本时，在仓库根目录打开一个**普通（不是管理员）的** cmd、PowerShell 或 Windows Terminal 窗口，运行：

```
orchestra.cmd --owned --agent-port --peek-port 7470
```

- `--peek-port 7470`：开页面，地址是 `http://orchestra.localhost:7470/`。不带这个参数就没有页面。
- `--owned`：开自有会话、派活台和刹车。不带它，页面只能看，不能派活。
- `--agent-port`：开 agent 侧请求口（一条 named pipe），让装了 seat bundle 的 DSH 能向 Orchestra **提请求**，每条请求都要你在页面上点「派出」或「拒绝」（见 3.5）。不用 DSH 的话可以不带。它有三个前提：
  1. **必须和 `--owned` 一起给**，否则 orchestrad 拒绝启动（`--agent-port only works with --owned`，见 `src/runtime/test-profile.ts`）。
  2. **要有 `--peek-port`**：请求要在配对页上等你处理。没有页面时请求口不开，控制台写 `the agent request port is off: no-page`。
  3. **至少一家自有会话开着**（Codex 或 Claude）。两家都没开时请求口不开，控制台写 `the agent request port is off: owned-off`。
  请求口开了，控制台打印一行，写明 pipe 名和令牌文件的位置（见下面「启动后控制台会打印」，代码在 `src/runtime/working.ts`）。DSH 那边的配置要照这两项写（`integrations/dsh-seat/README.md`）。
- `orchestra.cmd` 默认用仓库里的 `.tools\node24\node.exe`。在 worktree 里没有这个文件时，先设 `ORCHESTRA_NODE` 指向主检出目录的那份，例如在 cmd 里：`set ORCHESTRA_NODE=<主检出目录>\.tools\node24\node.exe`。
- 以管理员身份运行会被拒绝，orchestrad 直接退出。
- **配对码只在交互式控制台里打印**，条件是 stdin 和 stdout 都是控制台。Git Bash 的 mintty 窗口不算控制台，在那里启动会显示 `pairing is off`，页面就配不上对。请用 cmd、PowerShell 或 Windows Terminal。
- 停止：在这个窗口里按 Ctrl+C。orchestrad 会先结束所有自有会话（结束原因记为 daemon-stop），等 Claude 的 host 按顺序关掉（最多约 6 秒），关掉每个会话的 Job，再关库退出。
- 如果 orchestrad 是被别的程序用管道启动的（某个启动器或脚本），那个程序关掉管道或自己退出时，orchestrad 也会按 Ctrl+C 的顺序自己停下。从控制台启动不受影响；stdin 是空设备（NUL，例如脱离父进程的后台启动）或文件的，也不受影响。注意：被一个 Node 写的启动器直接启动、又没有让它脱离父进程时，启动器一死，Windows 会把 orchestrad 一起强行结束（Node 把子进程放进自己的 Job；实测过一次，当时没有自有会话在跑），这时 orchestrad 自己的停止顺序来不及运行。它的自有会话按机制推断也会跟着结束，但没有在会话还在跑时实测过（见第 5 节）。

启动后控制台会依次打印几行，比较重要的有：

- `orchestrad: pairing code 12345678`：配对码，见第 2 节。
- `orchestrad: procguard on …`：每个自有会话都在它自己的 Job 里，刹车可用。Job 是 Windows 的进程组，能一次整组结束。procguard 是仓库自带的 C# 小程序，每次带 `--owned` 启动时都用系统自带的 csc 重新编译（约 1–2 秒），放在数据目录的 `runtime\procguard\` 下；上次留下的 exe 不直接用。procguard 没开（编译失败、源码和钉住的校验值对不上等）时，自有会话整个关闭，控制台写明原因：每个自有会话都必须在自己的 Job 里。
- `orchestrad: owned Codex sessions on …` / `owned Claude sessions on …`：两家自有会话开没开。没开的会写原因，例如找不到 codex.exe。
- `orchestrad: agent request port on \\.\pipe\orchestra-agent-real (token in …\agent-port.token, new at every start): …`：请求口开了。真实 profile 的 pipe 名固定是 `\\.\pipe\orchestra-agent-real`；令牌文件在数据目录里（默认 `%USERPROFILE%\.orchestra\agent-port.token`，以这一行打印的路径为准），**每次启动都换新令牌**，关闭时删掉。没开时这一行写 `the agent request port is off: <原因>`。
- `orchestrad: working (real profile, pid …, data …)`：启动完成，这是最后一行。

> 说明：这条命令在真实数据上（也就是真实 profile）还没被实际跑过一次，`start-orchestra.cmd` 也没有实际跑过（只用 `/dry-run` 查过它找到的 node 和拼出的命令）。开发时 AI 助手按代-2 只用测试 profile（见 1.2），真实 profile 只由你启动、由你配对。第一次请你自己按第 6 节的清单走一遍。

它会在临时目录里建 `orchestra-test-tower`，写进一份合成数据（一个叫 shop 的项目，Claude、DSH、Codex 各有一棵会话树），然后打印启动命令，形如：


### 1.3 让自有会话在你的项目目录里干活（`--project-root`）

**不带这个参数时（默认）**，自有会话只在 Orchestra 自己建的目录里跑：真实 profile 下是数据目录里的 `work\<会话>`，每个会话一个新目录；测试 profile 下在测试目录的 `work\` 里。会话碰不到你的项目。DSH 请求里写的工作目录也只显示在卡片上，派出后会话照样在自建目录里跑。不带参数时这些行为和加这个功能之前一样，有测试反向核对过。

**什么时候用**：你想让自有会话（派活台派的，或 DSH 提请求、你点了「派出」的）直接读、改某个项目里的文件。

**怎么写**：启动时点名项目根，每个根一个 `--project-root`：

```
orchestra.cmd --owned --agent-port --peek-port 7470 --project-root D:\code\shop --project-root "D:\my work\blog"
```

用脚本的话，在 cmd 里运行 `start-orchestra.cmd --project-root D:\code\shop`（PowerShell 里写 `.\start-orchestra.cmd …`），或者给 `start-orchestra.cmd` 建一个快捷方式，在「目标」一栏后面追加这些参数。直接双击带不了参数。

- **只能和 `--owned` 一起给**，否则拒绝启动（`--project-root only works with --owned`）。
- **可以给多次，最多 16 个**。同一个写法给两次、或者换个写法（例如大小写不同）指向同一个目录，都拒绝启动。
- **必须是普通的绝对路径**，形如 `D:\code\shop`。相对路径、网络路径（`\\server\share`）、`\\?\` 开头的写法、含 `< > " | ? *` 或控制字符的、某一段以点或空格结尾的、`CON`、`NUL` 这类设备名，都拒。路径里有空格要加引号。
- **根在启动时就检查，第一个不合格的根让 orchestrad 拒绝启动**（退出码 24，和参数写错一样），控制台写明是哪个根、为什么：`orchestrad: refusing to start: --project-root "…" is refused: <原因>`。这时什么都不建、不拿锁。全部合格时控制台打印一行 `orchestrad: project roots for owned sessions: …`。
- **改根要重启 orchestrad**：根只在启动参数里，没有设置页。

**会被拒的目录和原因**：

| 什么样的目录 | 为什么拒 |
|---|---|
| 盘符根，例如 `D:\` | 整个盘不能当一个项目根 |
| 你的用户目录本身（`C:\Users\<你>`），以及它下面的 `AppData`（包括 `%TEMP%`）、`.ssh`、`.aws`、`.claude`、`.dsh`；系统目录、Program Files | 这些地方放着密钥、各家配置和系统文件。用户目录下面的普通子文件夹（例如 `C:\Users\<你>\code\shop`）可以 |
| orchestra 仓库本身、它的主检出目录 | 会话不在 Orchestra 自己的代码里跑 |
| Orchestra 的数据目录、Orchestra 读取的各家 harness 目录（Claude、DSH、Codex 的配置和记录目录） | r4 规格 §5.3 要求：会话的工作目录不能落在数据目录或任何 harness 配置目录里 |
| **把上面任何一个包在里面的上级目录** | 放行上级就等于放行了里面的受保护目录。例如 `G:\_Projects` 装着 orchestra 仓库，会被拒；`G:\_Projects\shop` 可以 |
| 不存在的、不是目录的 | 没有地方可跑 |
| 路径上有连接点（junction）、符号链接或 8.3 短名（形如 `PROGRA~1`）的 | 根必须就是它在磁盘上的真实路径，防止经链接绕到别处 |
| Orchestra 的读闸不肯看的（读闸是 Orchestra 读文件的唯一入口，名字里带 credentials 一类的路径它不看） | 判断不了它是不是目录，按拒绝处理 |
| 超过 260 个字符（或 780 字节）、含 bidi 方向控制字符的 | 页面显示不了、派活时也传不回来 |

测试 profile 下，项目根只能放在测试目录里面（测试目录本身装着数据目录，所以它本身也会被拒）；在项目根里面不按 AppData 那一行拒，其他照旧。真实 profile 没有这个例外，`%TEMP%` 下的目录会被拒。

**派活台怎么选**：放行了根以后，派活台多一个「工作目录」选择框。默认是「Orchestra 自建的工作目录（默认）」，其余选项就是你放行的那几个根，没有自由输入，也选不了根下面的子目录。没放行任何根时这个选择框不显示，说明行告诉你可以用 `--project-root`。选了根时，说明行按 harness 写清楚会发生什么：

- **Codex**：会话在这个根里跑，经你批准能改里面的文件。只在 Codex 的沙箱是只读时才启动，不是只读就以「设置和要求不符」结束。实测（codex 0.165.0）它写文件、跑命令会先来问你；没来问就跑了的，对话里会标出来；它读这个目录里的文件会不会先问你，未知。
- **Claude**：读、查找这个目录里的文件**不问你**（也就是说它能不经批准读整个项目）；写文件、跑命令每次先来问你。

**DSH 经 seat 提的请求**（seat 是 DSH 向 Orchestra 提请求的通道，见 3.5）：请求里带的工作目录（cwd）同时满足下面几条，卡片写「这在你放行的项目根里，派出后在 <目录> 里跑」，你点「派出」后会话就在那个目录里跑：

1. 落在某个放行的根里（根本身或它下面的子目录）；
2. DSH 写的路径里没有 `..`；
3. 路径上没有链接或连接点；
4. 过了上面那张拒绝表；
5. 存在，而且是目录。

任何一条不满足，会话照旧在 Orchestra 自建的目录里跑，卡片写「派出后仍在 Orchestra 自建的工作目录里跑」和原因（例如「启动时没有放行任何项目根」「它不在你放行的项目根里」「路径里有 ..」「这个目录不存在」）。不管哪种，派出都只有你在配对页上点（D8），DSH 不能自己派出，也不能指定根。

请求落在根里、派给 Claude 时，会话按「来源不可信」处理：它读、查找、写文件、跑命令**每次都先来问你**，比你自己在派活台选根更严。派给 Codex 时，读文件会不会先问你，未知。两种情况下，会话第一回合的最后一条回复都会交给发请求的 DSH 会话。

**项目根里的会话照样受这些约束**：Orchestra 自己不在项目根里建目录、不写文件（它对项目根只问「这是不是目录」）；改文件的是会话进程，每次都要你批准。会话在根里时，「工作目录外」就是这个根之外，碰根外的地方是高风险卡。根里面的 `.claude\`、`.codex\`、`.dsh\`、`.mcp.json`、`.git\hooks\`、`package.json`、`.husky\`、`.vscode\tasks.json`、`cordis.patch.yml` 这类会被别的程序执行的文件，改动也算高风险卡（要按住或键入确认，见 3.4）。会话页写「工作目录 <路径>（在你放行的项目根里）」，解锁后塔表里自有会话那一行多一段「在 <文件夹名>」。

## 2. 配对和解锁

两道门，作用不同：

| | 配对码 | 解锁码 |
|---|---|---|
| 作用 | 让这个浏览器能**看**页面 | 让这个标签页能**操作**自有会话（派活、发消息、审批、停止） |
| 在哪里看到 | 启动时打印在 orchestrad 的控制台里 | 点页面右上「解锁操作」后，才打印在控制台里 |
| 格式 | 8 位数字 | 8 位数字 |
| 有效期 | 启动后 10 分钟内有效，只能用一次（这次运行里只能配一个浏览器）；连错 5 次作废，累计错 20 次配对关闭。过期、作废或要配第二个浏览器，都只能重启 orchestrad 拿新码。配上以后的配对只在内存里，重启后要重新配 | 10 分钟内有效，只对这个标签页有效；连错 5 次要重新要码，累计错 20 次解锁关闭、要重启 orchestrad。同一个浏览器里另一个标签页解锁后，前一个标签页的解锁随即失效（一个配对只认最新的那个） |

打开 `http://orchestra.localhost:7470/`，按提示输入配对码。要操作时点「解锁操作」，回控制台看新打印的解锁码，填进去。

为什么要两道门：审批、拍板、刹车只能由你在配对过的页面上做（r4 规格的 D8 一条：这些人类动作不经 agent，也不会自动放行，超时就当拒绝）。码只打印在你面前的控制台里，别的程序读不到。

## 3. 页面

### 3.1 顶栏，从左到右

- **Orchestra · 塔**：首页叫「塔」，是你 → agent → 分身（subagent）的跨项目会话树。有事在等你时，浏览器标签标题前面会出现件数，形如「(3) Orchestra · 塔」。**标题的数字 = 树里在等你的节点数 + 还在等你处理的 DSH 请求数**。页面在后台时它也会动（每 10 秒读一次）。
- **测试数据**：只在测试 profile 下出现。
- **计数：等你 N / 出错 N / 在跑 N**：点一下只看这一类，再点一下取消。它们是筛选，数字等于点开后的行数（T3：计数等于它链接的列表长度）。所以顶栏的「等你」**只数树里的节点，不数 DSH 请求卡**：请求卡不是树里的行，点开也不会出现。有 DSH 请求在等时，标题的数字会比顶栏「等你」大，差的就是请求卡的张数（它们在「等你」钉栏里，见 3.5）。观察到的会话这一版不判定出错，没有判定规则时「出错」不显示，免得把「没看」写成「0 个」。
- **来源**：只在某个来源读取出错时出现，写明是哪一家、什么错。
- **更新时间**：多久前拿到的数据；太久没拿到新数据会写「已 N 秒没拿到新数据」。
- **关于数据**：诚实声明、每家来源读了多少、哪些判定规则没在真实样本上测过（写「没测过」）。
- **主题**：跟随系统 / 浅色 / 深色。
- **解锁操作 / 已解锁**：见第 2 节。
- **派活**：打开派活台，见 3.3。没解锁时写「派活 · 先解锁」，点了先解锁。

### 3.2 塔表

- 「等你」钉栏：所有在等你的事，有期限的按剩余时间排在前面。
- 树：每行一个会话，缩进表示层级。「子·错·等」一栏是这一行下面子树里的会话数、出错数、等你数。
- 「归属」一栏：「只读」是观察到的会话，「自有」是 Orchestra 自己开的，「被占用」是别人正在驱动的。
- 状态前带 ≈ 的是推测（从记录或文件修改时间推出来的），不是会话自己登记的。
- 「已回报」只表示分身把结果交回去了，不等于验收通过。
- 「你」那一行显示最近一次派活。没有可显示的派活时，它分三种写：
  - 解锁前：「派活记录：未知」。塔表数据不说派活台开没开，解锁后才读得到。
  - 派活台开着、这份数据里没有派活记录：「还没派过活」，旁边有一个「派活」按钮，和顶栏那个一样。
  - 派活台没开（例如不带 `--owned` 启动）：「现在不能派活」，括号里写原因。这时 orchestrad 也不读以前的派活记录，所以不说「没派过」。

### 3.3 派活台（顶栏「派活」按钮）

1. 写一句话任务。
2. 可选：点 **给建议**。先跑几条固定规则，再问一次 magpie 上的路由模型（默认 `zcode/GLM-5.3`，最多约 20 秒），给出「派给谁？」卡片：首选、备选，各自写明来源（规则 / 路由模型）和理由。
3. 选好 harness（Codex 或 Claude）和模型，点 **派出**。**只有点「派出」才会开会话**，建议本身从不开会话，也从不自动派活。
4. 建议后改过那句话，卡片作废，派出时记成手动选择。

限制：两家合计同时最多 3 个自有会话在跑，满了要先结束一个。模型只能选 magpie 上的 `zcode/*`、`opencode-go/*`、`codex/*`（Claude 不收 `codex/*`）。工作目录默认是 Orchestra 自己建的：真实 profile 下在数据目录的 `work\<会话>`。启动时用 `--project-root` 放行了项目根，派活台会多一个「工作目录」选择框，可以选其中一个根（见 1.3）。

### 3.4 审批

自有会话要跑命令、改文件时，会先来问你，卡片出现在「等你」钉栏和对话里。

- **允许 / 拒绝**：参数完整显示出来时才给「允许」；内容太长显示不全的，只能拒绝。
- **高风险**（shell 命令、联网、写工作目录外）：要**按住「允许」1 秒**（或按住 Enter），或者点一下后输入确认词 **放行**。
- 列表刚变过（750 毫秒内）的允许无效，页面会提示「列表刚变过，等它停稳再允许」。
- **30 分钟没人处理就自动拒绝**，卡片上有倒计时「剩 … 自动拒」。
- 碰到受保护的位置（数据目录、各家的配置目录、AppData、仓库等），Orchestra 直接拒绝，不弹卡，对话里会写明。
- 浏览器通知和通知栏里不放「允许」按钮，只提醒你回页面。
- 观察到的会话（Claude、DSH、Codex 自己开的）在等你时，这里只读：请到它自己的界面里处理。

### 3.5 「等你」栏里的 DSH 请求卡

只在 orchestrad 带 `--agent-port` 启动、并且某个 DSH 装了 seat bundle（`integrations/dsh-seat`）时出现。DSH 的主 agent 调 `subagent_codex_governed` 或 `subagent_claude_governed` 时，**不会启动任何进程**，只是向 Orchestra 提一条请求，请求在「等你」栏里变成一张卡，和审批卡一起按剩余时间排。

- **没解锁时是占位卡**：「以 DSH 名义请求派 Codex：任务内容和请求方解锁后可见 · 剩 9:45 自动拒」，按钮是「先解锁」。这时页面只知道哪一家、还剩多久，看不到任务原文和请求方。
- **解锁后是完整卡**：任务全文；「自称来自 DSH 会话 <id>（未核实）」，没给 id 时写「未知」；「它想在 <目录> 干活；派出后仍在 Orchestra 自建的工作目录里跑（<原因>）」，或者在你用 `--project-root` 放行的根里时写「这在你放行的项目根里，派出后在 <目录> 里跑」（条件见 1.3）；派出会用的模型和它的来源（路由模型建议、规则建议，或者默认值和为什么是默认值）。
- **「自称来自…（未核实）」的意思**：请求方是谁，是它自己报的，Orchestra 没有核对（没有校验管道那头是哪个进程）。不要把它当成身份。
- **「派出」**：开一个自有会话，任务就是卡上的原文，模型就是卡上写的那个。之后它和你自己派的会话一样：要审批的照样来问你，三档停止照样能用。会话第一回合结束后，最后一条消息交回给 DSH；这只表示「那一回合回来了」，不是工作做好了的判定。
- **「拒绝」**：DSH 那边收到「人在 Orchestra 配对页上点了『拒绝』」，那次委派以拒绝结束。
- **到点自动拒**：10 分钟没人处理，请求自动变成「已到期」，按拒绝算（超时即拒）。卡上一直有倒计时「剩 … 自动拒」。
- 派出键和审批的允许键一样，「等你」栏刚变过（750 毫秒内）时点了无效。
- DSH 那边中断了这次委派，请求随之撤回：还没派出的卡直接消失；已经派出的会话按「结束会话」的正常顺序收尾，不是刹车。
- 页面在后台时，新请求会发浏览器通知，通知里没有「派出」按钮。
- 请求只在 orchestrad 的内存里：重启后全部丢失。

2026-11-03 在测试 profile 里用内置浏览器走过占位卡、完整卡、「派出」和「拒绝」两条路径；orchestrad 自己的 10 分钟到期也在测试 profile 里实跑过。

### 3.6 对话区和三档停止

选中一个自有会话，底部是「发给 → 它」的输入框：回合还在跑时发出的消息会插进当前回合（插话），空闲时开始新的一回合。消息不能以 `/` 开头，最多 2048 字节。

停止键有三档，一档比一档重：

| 按钮 | 做什么 | 怎么按 |
|---|---|---|
| **中断这一回合** | 请它停下当前这一轮，会话还在，可以接着发消息 | 点一下 |
| **结束会话** | 结束这个会话：拒掉它的待审批，关掉它的进程，它的 Job 随之关闭，Job 里剩下的进程也一起结束 | 3 秒内点两次 |
| **刹车（停它 Job 里的所有进程）** | 立即结束它整个 Job 里的所有进程（包括它跑的命令直接起的子进程），拒掉它的所有待审批，会话以「你踩了刹车」结束。经任务计划、WMI 或已在运行的程序（资源管理器、浏览器等）间接启动的进程不在 Job 里，刹车管不到，是否还在未知。会话已在结束中、进程还没关时，也还能刹车 | 3 秒内点两次 |

procguard 没开时自有会话整个关闭，不会出现没有 Job 的会话。常驻的 procguard 中途退出时，刹车键还在，停止键下面的说明行写「刹车说不出结果：…」：刹车仍会结束包装进程、让 Job 关闭，但停了什么、是否全停，未知。

## 4. 只能看的部分

- 观察到的 Claude、DSH、Codex 会话：只读。Orchestra 不给它们发消息、不批准、不停止。
- 页面不改你任何 harness 的配置目录（`~/.claude`、`~/.codex`、`~/.dsh` 等），只读取。
- 页面顶栏没有全局刹车。M0（第一个里程碑，只读观察层）预留的 `/api/brake/plan`、`/api/brake/execute` 两条路由还没有实现；刹车只对单个自有会话有效。

## 5. 已知限制

从 `docs/plans/2026-11-02-orchestra-app-plan.md` 的「分歧和残余风险」一节摘出来的，跟日常使用关系最大的几条：

- **Codex 在 Windows 上的沙箱只能只读**：写入型沙箱在 Windows 上不生效，所以 Codex 每次写文件、跑命令都会先来问你。要改得装额外组件并提权，所以没开。
- **花费数字不可信**：Claude 会话对话里的「花费」是 Claude CLI 按它自己的价目表估的。走 magpie 的 zcode / opencode-go 模型不在它的价目表里，真实花费未知。
- **Codex 版本钉死**：只认 codex-cli 0.165.0。`npm i -g` 升级后，新会话会以「设置和要求不符」结束，并写明实际版本。
- **Codex 和你的全局 skills**：私有配置目录挡不住 `~/.agents/skills`。现在已经不把它写进模型的提示词，模型看不到；但 codex 进程自己会不会扫描那个目录，未知。
- **重启后看不到旧对话**：orchestrad 重启后，之前没结束的自有会话显示「状态未知」，不续跑、不重发；对话内容只在旧进程内存里，重启后看不到。派活建议只在内存里存 30 分钟，重启后作废。
- **Job 挡不住同一用户的恶意进程**：Job 只防正常的进程树泄漏。同一用户下的进程能从包装进程里复制出 Job 的句柄，改掉它的限制。
- **间接启动的进程不在 Job 里**：agent 的命令经任务计划、WMI，或交给已经在运行的程序去打开的东西，是 Job 外的进程起的，刹车和结束会话都管不到，是否还在未知。
- **orchestrad 被强杀时**：会话还在跑时强杀 orchestrad（任务管理器结束进程），按机制推断包装进程会跟着死，Job 也跟着关，但没有实测过。被强杀时 orchestrad 自己的停止顺序不会运行。
- **派活台是简化版**：只有五条固定规则和一次路由模型。r4 规格要的完整路由内核（硬过滤、证据门、滞回、影子模式）没做。
- **观察到的会话不判定出错**；Codex 的「可能在等你」可能漏掉（列表先按时间截取再读文件）。
- **页面只在测试 profile 里走过**：2026-11-03 在测试 profile 里用内置浏览器走过派活台的建议、派出、拒绝、按住 1 秒允许、中断、刹车、结束会话、亮暗两套主题和 375px 窄屏，修了两处布局问题：8bc1bd9（「等你」栏为空时，发送框和停止键被挤出屏幕）、e483824（手机宽度下自有会话的整块内容，包括状态、按钮、审批卡和对话，被藏起来）。真实 profile 下的页面仍只能由你自己走（代-2），见第 6 节。遇到问题请记下来。
- **DSH 请求卡的残余**：请求方是自报的（「未核实」）；读到令牌文件的同用户进程都能提请求（但每条都要你点）；请求只在内存里，重启就丢。细节见 `integrations/dsh-seat/README.md` 的「已知限制」。
- **node.exe 没有钉哈希**：只检查它存在、不是链接。
- **项目根（`--project-root`，见 1.3）的残余**：只在测试 profile 里用 Codex 实跑过一次（会话在根里写文件、结束后 Job 里没有剩下的进程）；Claude 会话在项目根里跑没有实测过；真实 profile 下带 `--project-root` 启动没有跑过（代-2）。两个会话放在同一个根里可以同时改同一批文件，页面不告警（r4 规格 §10.8 要的「两个写者」告警没做）。根里面的 `package.json` 整个文件算受保护，不看是不是改了 scripts；`.git\config`（能改 git 钩子的位置）不在受保护清单里。在项目根里给 Codex 加「来源不可信」时更严的审批策略没做（没实测过），所以 DSH 请求派给 Codex 时，它读文件会不会先问你，未知。

## 6. 第一次在真实数据上启动：自查清单

这些开发时没做（见 1.1 的说明），请你自己走一遍：

1. 按 1.1 启动（双击 `start-orchestra.cmd`，或手动运行 `orchestra.cmd --owned --agent-port --peek-port 7470`），确认控制台打印了配对码、`procguard on`、两家 `owned … sessions on`、`agent request port on \\.\pipe\orchestra-agent-real (token in …)`，最后一行是 `working (real profile …)`。
2. 启动后 10 分钟内打开页面配对（配对码只能用一次，过期要重启），塔表应该显示你自己的项目和会话。顶栏的数字点开，行数应该和数字一样。
3. 解锁，用派活台开一个 Codex 会话，任务写「只回复一个词 ok，不要用任何工具」，等它变成「空闲」。
4. 点「结束会话」（3 秒内点两次），对话里应出现「它的 Job 里没有剩下的进程」一类的说明。
5. 在控制台按 Ctrl+C，确认 orchestrad 退出；任务管理器里不应留下 codex.exe、procguard.exe。
6. 有不对的地方，数据目录下的 `run\orchestrad.log` 是诊断日志（配对码和解锁码不进日志）。
